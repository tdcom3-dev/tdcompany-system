# TD Company System

대표가 요청하면 실장이 업무를 계획하고, 조직도에 등록된 역할 봇이 skill에 따라 산출물을 작성하는 개인 개발용 업무실입니다.

**현재 단계:** 기본 구조와 로컬 앱. td-hr.app 분석 결과는 아직 연결되지 않았으며 최초 실행에는 예시 조직이 들어 있습니다.

## 시작

Node.js 24 이상이 필요합니다. 저장소 루트에서 실행합니다.

```sh
npm ci
npm run dev
```

개발 화면 포트는 5173, API 포트는 3001입니다. 서버는 127.0.0.1에만 바인딩합니다. 빌드 후 `npm start`를 실행하면 API 서버가 `dist` 화면도 제공합니다.

```sh
npm test
npm run build
npm start
```

브라우저 검증은 빌드 후 `npm run test:ui`로 실행합니다. 시스템 Chromium(`/usr/bin/chromium`) 또는 `CHROMIUM_PATH`를 사용하며, 다른 환경에서는 `npx playwright install chromium`으로 설치할 수 있습니다. 테스트는 임시 DB를 사용합니다.

## 업무 흐름

1. **조직도**에서 회사 정보·역할·skill JSON을 가져옵니다. 내보내기로 같은 형식의 템플릿을 받을 수 있습니다.
2. **Skills 라이브러리**에서 역할 지침을 편집하거나 Markdown 파일을 불러와 저장합니다.
3. **새 업무 요청**에 목표와 산출물을 작성합니다. 역할을 직접 선택하거나 기본 키워드 배정 규칙을 사용합니다.
4. 계획을 확인한 후 **실행**합니다. 선행 산출물을 다음 역할에 전달하며 순서대로 진행합니다.
5. 산출물을 검토하고 **최종 승인**하면 업무가 완료됩니다.

실장은 현재 규칙 기반 오케스트레이터입니다. 기획 → 이미지 → 영상 → 개발 → 운영 → 검수의 순서로 해당 역할들을 배정합니다. 조직의 `reportsTo`는 보고 관계를 표현하며, 실행 의존성은 단계 순서로 별도 관리합니다. 회사 분석 기반의 자율 계획·재배정과 동시 실행은 후속 확장 대상입니다.

업무 생성 당시 회사 정보·역할·skills는 업무에 복사하여 보존합니다. 실패한 단계부터 재시도하며 완료된 산출물은 유지합니다. 서버 재시작 시 진행 중 업무는 확인 필요 상태로 복구됩니다. 외부 API 응답 저장 전 중단된 텍스트·이미지 작업은 재시도 시 중복 과금될 수 있으므로 공급자 사용 내역을 확인하세요. 영상은 저장된 공급자 작업 ID를 재사용합니다.

## AI 연결

환경 설정에 `AI_API_KEY`를 안전하게 등록하거나, 로컬 개발에서 `.env.example`을 참고하여 Git에서 제외되는 `.env`를 작성합니다. 키를 채팅·커밋·조직도 JSON에 포함하지 마세요. 설정 변경 후 API 서버를 재시작합니다.

| 변수                 | 기본값 / 용도                                         |
| -------------------- | ----------------------------------------------------- |
| `AI_API_KEY`         | 생성 API 인증. 미설정이면 계획·조직 관리만 가능       |
| `AI_BASE_URL`        | `https://api.openai.com/v1`                           |
| `AI_TEXT_MODEL`      | `gpt-4.1-mini`, Chat Completions                      |
| `AI_IMAGE_MODEL`     | `gpt-image-1`, base64 이미지 응답                     |
| `AI_VIDEO_MODEL`     | `sora-2`, Videos 작업 생성·조회·다운로드              |
| `DATA_DIR`           | `.data`, SQLite 및 산출물 경로                        |
| `PORT`               | `3001`, API/빌드 앱 포트                              |
| `NODE_USE_ENV_PROXY` | 관리형 클라우드에서는 `1`로 설정해 주입된 프록시 사용 |

AI 키 설정 여부와 실제 서비스 접근 성공은 다릅니다. 모델 사용 권한 및 API 호환성이 필요합니다. 실제 실행 버튼을 누르면 생성 비용이 발생할 수 있습니다. 현재 자동 테스트는 가짜 공급자로 실행 흐름을 검증하며 실제 유료 서비스 성공을 보장하지 않습니다.

이미지는 PNG, 영상은 4초 세로 MP4를 요청합니다. 이전 단계의 텍스트를 전달하며 이미지·영상 바이너리는 후속 모델에 첨부하지 않습니다. 검수 봇은 이 제한을 명시하도록 설정되어 있고 **최종 시각 검수는 대표가 해야 합니다**. 개발 봇은 설계와 코드 초안을 생성하며 코드 실행·Git 푸시·배포는 수행하지 않습니다.

## 조직도 교환 형식

`examples/organization.json`이 예시입니다. td-hr.app의 실제 내보내기/API 형식이 확정되면 어댑터를 추가합니다. 지금은 직접 연동을 가정하지 않습니다.

```json
{
  "version": 1,
  "company": { "name": "회사명", "description": "사업과 업무 맥락" },
  "roles": [
    {
      "id": "planning",
      "name": "기획팀",
      "category": "planning",
      "description": "기획 담당",
      "reportsTo": null,
      "skillIds": ["planning-skill"]
    }
  ],
  "skills": [
    {
      "id": "planning-skill",
      "name": "기획 skill",
      "instructions": "Markdown 지침"
    }
  ]
}
```

카테고리: `planning`, `image`, `video`, `development`, `operations`, `review`. ID 중복, 없는 skill 참조, 없는 상위 역할, 순환 보고 관계는 가져오기 전에 거부합니다. `reportsTo: null`은 실장 직속입니다. 조직도 교체는 기존 업무를 삭제하지 않습니다.

## 구조와 데이터

- `src/`: 한국어 React 업무실, 조직도, skill 편집, 연결 상태
- `shared/domain.ts`: 교환 형식·입력 검증·업무 타입
- `server/planner.ts`: 기본 업무 배정
- `server/runner.ts`: 의존성 실행, 실패 복구, 결과 취합
- `server/provider.ts`: 텍스트·이미지·영상 공급자 어댑터
- `server/store.ts`: SQLite 상태 저장
- `tests/`: 자동 배정·오류 처리·영속성·HTTP 흐름 테스트

`.data/`는 Git에서 제외되며 회사 정보와 업무 산출물이 저장됩니다. 보관이 필요한 경우 이 디렉터리를 별도 백업하세요. 현재 로그인·테넌트 격리·분산 큐가 없으므로 공개 서비스나 여러 서버 인스턴스로 배포하기 전 별도 구현이 필요합니다.
